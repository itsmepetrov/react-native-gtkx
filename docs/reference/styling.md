# Styling

Every component takes the same flat `style` object RN components take
(`ViewStyle`/`TextStyle`/`ImageStyle`, all aliases of one style bag on this
platform). The pipeline splits that object in two: `StyleSheet.flatten` →
`splitStyle` divides it into a **layout** half and a **visual** half. Layout
keys go to the Yoga engine (`LayoutNodeApi.setStyle`) and never reach CSS;
visual keys are turned into GTK CSS (`visualStyleToCss`) and applied through a
memoized class registry, one class per unique declaration. `overflow` is the
one key that crosses both halves — see below.

Layout fidelity is exact: every container runs its own layout manager that
obeys only what Yoga computes, so a GTK widget's own minimum size never leaks
into the layout, a window shrinks as freely as Yoga allows, and
`Dimensions.get("window")` reports the same thing RN's app window reports —
the window's content area under its header bar.

A property's status is one of:

- **supported** — works fully;
- **partial** — works, with the caveat in its note;
- **ignored** — outside the frozen style contract; a value is accepted, a
  warning fires once per key, and the value is dropped.

## Layout (routed to Yoga)

`alignContent`, `alignItems`, `alignSelf`, `aspectRatio`, `bottom`,
`columnGap`, `direction`, `display`, `flex`, `flexBasis`, `flexDirection`,
`flexGrow`, `flexShrink`, `flexWrap`, `gap`, `height`, `justifyContent`,
`left`, `margin`, `marginBottom`, `marginHorizontal`, `marginLeft`,
`marginRight`, `marginTop`, `marginVertical`, `maxHeight`, `maxWidth`,
`minHeight`, `minWidth`, `overflow`, `padding`, `paddingBottom`,
`paddingHorizontal`, `paddingLeft`, `paddingRight`, `paddingTop`,
`paddingVertical`, `position`, `right`, `rowGap`, `top`, `width` — all
**supported**, with behavior defined by the layout engine itself.

`overflow` is the one key that does not stop at Yoga: Yoga needs it while
measuring (a scroll node's main axis is unconstrained), and the widget needs
it to clip. GTK4 CSS has no `overflow` property, so this is a direct widget
call rather than a CSS declaration — the only style outside `transform` whose
GTK half is not CSS. `hidden` clips paint and hit-testing to the widget's CSS
padding box, rounded by `borderRadius`; `scroll` clips the same way and adds
no scrolling of its own — matching RN, where only a `ScrollView` scrolls;
`visible` (the default) lets children paint past the container, as in RN.

## Colors

| Format                                     | Status    | Note                                                                                                                                             |
| ------------------------------------------ | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| named colors (CSS Color 4), `transparent`  | supported | normalized to `rgb()`/`rgba()`                                                                                                                   |
| `#rgb` / `#rgba` / `#rrggbb` / `#rrggbbaa` | supported | normalized to `rgb()`/`rgba()`                                                                                                                   |
| `rgb()` / `rgba()`                         | supported | both comma and space syntax (`rgb(255 0 0 / 0.5)`); channels as numbers or percentages                                                           |
| `hsl()` / `hsla()`                         | supported | hue as a number or with `deg`; saturation/lightness strictly as percentages; converted to `rgb()`/`rgba()`                                       |
| `PlatformColor("accent-bg-color", ...)`    | supported | resolves to `var(--accent-bg-color, ...)` — Adwaita theme variables (libadwaita ≥ 1.6); `@name` reaches a legacy GTK named color as the fallback |
| `var(--...)` / `@name` as a plain string   | supported | passed through without normalization                                                                                                             |
| an invalid string                          | ignored   | the color parses to nothing; the declaration is dropped, with one development warning per distinct value                                         |

## Not part of the style contract

Any key outside `LayoutStyle`/`VisualStyle`/`BehavioralStyle` — `elevation`,
`filter`, `mixBlendMode`, `textTransform`, `tintColor`, and the like — is
accepted, warned about once per key, and dropped. `pointerEvents` and
`zIndex` are `BehavioralStyle`: each is read by the component that implements
the behavior, not by either half of this pipeline (see
[Core components](components-core.md#layout-paint-and-hit-testing) for both).
