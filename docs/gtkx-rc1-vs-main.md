# gtkx rc.1 ↔ main: расхождения и план миграции на rc.2

Мы приколочены к `@gtkx/*@1.0.0-rc.1`, но main уже ушёл вперёд, и часть нашего
кода — сознательные обходы отсутствующих в rc.1 возможностей. Каждый обход
помечен в коде тегом `RC1-WORKAROUND(<имя>)` — `grep -rn "RC1-WORKAROUND"`
даёт полный список мест. При выходе rc.2 пройтись по таблице сверху вниз.

**Правило:** добавляешь новый обход — добавь тег в код и строку сюда.

## Не-обходы (особенности, которые скорее всего останутся)

- 64-битные FFI-значения приходят BigInt → `toNumber()` на границе (`gtkx-bridge/measure.ts`);
- имена сигналов — kebab-case ("value-changed"); сигналы не передают эмиттер (виджет брать из ref);
- запросы ролей в тестах — enum `Gtk.AccessibleRole`, не строки;
- `npm install` прунит codegen-store (`node_modules/.gtkx` не в lockfile) → после установки нужен `npm run codegen` — это поведение npm, не gtkx;
- измерение незамапленных виджетов даёт 0 (офскрин-пробы Label — исключение) → ремер по сигналу `map` + пере-коммит измеряемых листьев каждый flush (`layout/node.ts`).

## Процедура при выходе rc.2

1. Обновить пины `@gtkx/*` в package.json (корень, spike, examples, template), `npm install && npm run codegen`;
2. Прогнать всё: `npm run typecheck && npm test && npm run test:gtk` + сборки examples;
3. Пройтись по таблице: для каждого пункта — проверить, закрыт ли, мигрировать, снять тег;
4. Обновить этот файл и `spike/RESULTS.md`-отсылки.
